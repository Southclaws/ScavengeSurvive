# Runbook

Everything needed to build, run and debug the open.mp port on this machine.
Repository lives at `/root/scavengesurvive`, work is on the `openmp` branch.

## One time host setup

Already done on this machine. Repeat on any new 64 bit Linux host, because
open.mp ships a 32 bit Linux server only.

```
dpkg --add-architecture i386
apt update
apt install -y libc6:i386 libstdc++6:i386 libgcc-s1:i386 libatomic1:i386 libuuid1:i386
```

sampctl 1.14.1 is installed at `/usr/local/bin/sampctl` from the
`sampctl_1.14.1_linux_amd64.tar.gz` release asset. sampctl itself is a 64 bit
binary. Only the server and its plugins are 32 bit.

Export a GitHub token before any ensure. This project has enough dependencies to
exhaust the 60 requests an hour that unauthenticated callers get.

```
export SAMPCTL_GITHUB_TOKEN="$(gh auth token)"
```

## Daily commands

| Goal | Command |
| --- | --- |
| Install or update dependencies, plugins, components, server | `sampctl ensure` |
| Compile the gamemode | `sampctl build` |
| Run the server alone | `sampctl run` |
| Run the server under the Runner | `go build -o ss . && ./ss` |
| Run the Go tests | `go test ./runner/` |

The Runner is the normal way to run it. It restarts the server when it exits,
reformats the logs, serves the update endpoint on port 7788 and optionally
bridges to Discord.

## Where things live

| Path | What it is | In git |
| --- | --- | --- |
| `pawn.json` | Package and runtime definition. The source of truth. | yes |
| `config.json` | Generated by sampctl from `pawn.json`. Do not edit. | no |
| `omp-server` | The open.mp server binary, downloaded by sampctl. | no |
| `components/` | open.mp components, including sscanf. | no |
| `plugins/` | Legacy SA-MP plugins. | no |
| `dependencies/` | Pawn source dependencies and include paths. | no |
| `pawn.lock` | Resolved dependency versions. | no |
| `gamemodes/ScavengeSurvive.amx` | Build output, around 58 MB with `-d3`. | no |
| `scriptfiles/data/` | Databases, settings, player and world state. | no |
| `misc/settings.ini.example` | Gameplay settings to start from. | yes |
| `log.txt` | Server log. Removed by the Runner between runs. | no |

## Changing configuration

Server configuration, meaning ports, hostname, player limit and rcon password,
lives in the `runtime` section of `pawn.json`. Editing `config.json` achieves
nothing, because the next run regenerates it.

Gameplay configuration lives in `scriptfiles/data/settings.ini`, which the
gamemode creates empty on first boot and fills from its own defaults. Copy
`misc/settings.ini.example` over it to start from the project's values. The
Runner can also write that file at startup from the `SETTINGS_OVERRIDE`
environment variable.

## Restarting

Three different things are called a restart:

- `gmx`, which restarts the gamemode inside the running server. This is what the
  in game `/restart` command does.
- The Runner's process restart, which kills the server process group and starts
  it again. Triggered when the gamemode prints `[OnScriptExit] LAST_EXIT`.
- The scheduled update restart. When the Runner sees a newly compiled `.amx`, it
  answers the gamemode's poll of `localhost:7788/update` with a countdown, and
  the gamemode schedules a restart an hour out.

## Build warnings

A clean build reports 95 warnings. 88 are inside third party dependencies, which
sampctl re-downloads, so they cannot be fixed from this repository. The other
seven are pre-existing unused assignments and shadowed variables in the
gamemode, unrelated to open.mp.

The gamemode itself has no tag mismatch and no deprecation warnings. If a change
introduces one, fix the code rather than defining NO_TAGS, MIXED_SPELLINGS,
LEGACY_SCRIPTING_API or SAMP_COMPAT, which switch the checks off everywhere.

## Troubleshooting

**"error while loading shared libraries" on startup.** A missing 32 bit library.
Run `ldd omp-server` and install the i386 package that provides what is missing.

**"Function not registered: UUID".** `libuuid1:i386` is not installed. The uuid
plugin failed to load, which the log says a few lines above the error.

**"cannot read from file" for a plugin include.** The dependency is declared with
`component://` or `plugin://` only, which installs the binary without adding the
package's include path. Add an `includes://` line for the same repository, as
sscanf does.

**403 rate limit during ensure.** Set `SAMPCTL_GITHUB_TOKEN`.

**"text file busy" when ensure replaces omp-server.** A server is still running.
Stop it first.

**"integrity mismatch" for a dependency.** `pawn.lock` disagrees with what is on
disk. Delete `pawn.lock` and the offending directory under `dependencies/`, then
ensure again.

**Long callback execution warnings during startup.** These mean the
`long_call_time` runtime setting has gone missing from `pawn.json`. It is
supposed to be zero, so that crashdetect stays quiet until the gamemode enables
long call detection itself.

**The server keeps running after you stop the runner.** It should not. The
runner stops its whole process group and waits for it, and kills it after
fifteen seconds. If you see an orphan, stop it with `pkill omp-server` and treat
it as a bug.

**New warnings after changing a callback or a dependency.** The open.mp includes
tag parameters that take a limited set of values, so a bare integer warns. Use
the named constant the include declares rather than silencing it. The reference
is `documentation/readme-intermediate.md` in the omp-stdlib dependency.

**A build error inside a macro that makes no sense.** Add `-l` to the build args
in `pawn.json` and run `sampctl build`. The compiler writes a fully preprocessed
`gamemodes/ScavengeSurvive.lst` and stops. Compare the expansion of the broken
line with a working one. This is how the F@T collision was found. Remove the
flag afterwards, since it stops the build from producing an amx.
